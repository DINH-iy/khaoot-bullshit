# Feature feedback build plan

Updated 20 November 2026. This covers the 41 feature requests in the feedback export and the background music playlist follow-up from this conversation. Exported reports use the full ID searchable in **Admin → Feedback**. All 41 were marked **New** in the export. The status below describes what is implemented in the checkout. [Tester feedback tracker](tester-feedback.md)

## Build order

1. **Live round controls are implemented.** The four reports below track automated coverage and remaining real-phone checks.
2. **Player and host controls are implemented.** The reports below record verification and the remaining physical-device and Pi checks.
3. **Voting and results controls are implemented.** Auto-reveal and the host phone came first, followed by result cards, multi-select and ranked ballots, the private birthday vote, and configurable drawing and minigame countdowns. The reports below track remaining device checks.
4. **Authoring and presentation changes are implemented.** Writing opens directly, with prompt starters inside the scene. The editor has an Intro template, Space and three planet presets, a first-run tour, customizable shortcuts, saved edit history, undoable scene-type replacement, and Ctrl/Command-drag selection. Scene and result transitions, the join form, and feedback attachments are covered below.
5. **The new party features are implemented.** This includes Speed run and its course editor, the animation relay, optional microphone play, player effects, chat, Creature duel, scoreboard reactions and background playlists. Remaining live checks are tracked below.

### Phone input inventory

- Touch and tap timing support reaction games, direction controls and drag ordering. The drawing pad supports touch and pointer strokes. Test short viewports with browser bars visible.
- Photos, video and drawing are available through the existing upload and drawing flows. Phone audio playback and vibration vary with browser permissions, device support and user gestures.
- The microphone test uses a browser permission prompt and a local Web Audio analyzer. Clap the beat uses the same local analyzer to detect brief sounds during its scoring windows. Tap is also available throughout play. Motion sensors and location are currently unused. [Microphone access](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia), [Web Audio input measurement](https://developer.mozilla.org/en-US/docs/Web/API/AnalyserNode/getFloatTimeDomainData).
