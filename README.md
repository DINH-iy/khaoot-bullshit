# Party game builder

Browser frontend and authoritative TypeScript/Node.js backend. The current checkpoint has PostgreSQL/Prisma, durable game commands, verified room credentials, Socket.IO, and minimal host/phone connection-test screens. It is not the complete party-game builder. Product decisions live in [APP_PLAN.md](APP_PLAN.md).

**Patch notes** on the join screen and host menu shows the update history, newest day first. New commits appear automatically when you open Patch notes in development or rebuild the hosted app. Descriptive commit titles appear as written. Generic titles such as “Save” get an English summary of the areas changed. Builds without the Git history still include the curated notes.

## Requirements and local commands

Use Node.js 24 LTS (`nvm use`) and npm 11.

```sh
npm ci
cp .env.example .env
npm run dev
```

Frontend: http://127.0.0.1:5173. Backend: http://127.0.0.1:3001. Vite proxies `/api` to the backend. To override the API port, update both `.env` and the development proxy. Nothing is deployed automatically.

```sh
npm run check       # types, tests, and production builds
npm test            # deterministic offline backend tests
npm run test:watch
npm run build
npm start -w @party/server
```

Build contracts before standalone package development/tests; the root commands handle this. Restart development after changing contracts, or rebuild contracts while watching. Production web files land in `apps/web/dist`. The API serves them only when `SERVE_WEB=true`, which the host launcher, the public rehearsal launcher and the browser tests set; it is off by default. Permanent deployment comes in a later slice.

## Hosting a room

Step-by-step instructions for starting (on this computer or with a temporary public test link for phones), checking what runs (`npm run status`) and taking everything down (`npm run stop`) are in [Running the party game](docs/guides/running.md).

```sh
npm run db:up && npm run db:migrate:deploy   # once, or after new migrations
npm run host
```

`npm run host` builds the app, starts it on this computer and opens the host menu in your browser, already signed in as the owner. Pick a built-in game, open a room, and share the room code or QR. To try a game alone, **Open test bench ↗** (in the room's *Shared screen & invite*) shows the host screen with virtual phones next to it, each its own player, with up to four in a 2 × 2 grid; *Real phones can join too* lets real players join as well (the room setting *Test bench phones may join* is switched on by opening the bench). The owner can change a built-in game with **Edit this game** (their own version, edited and published like any game; once published the menu and rooms use it, and **Restore original…** goes back). The first run generates `ROOM_TOKEN_SECRET` and `LOCAL_OWNER_TOKEN` into the ignored `.env`. This mode only reaches browsers on the same computer; `npm run network:public` opens the same menu on a temporary public address for phones on other networks. The host menu also has "Your games": create a game (blank, a copy of a built-in, or a copy of one of your own games: **Copy** next to a game, or ☰ → *Make a copy of this game* in the editor, which saves first and opens the copy with its card layout and groups), see its problems per scene, publish it, and open a room for the published version. Each game opens in the Flow editor (`/?edit=<game>`): scene cards on a canvas (right-click empty canvas to add a scene there; the add menu has tabs (Rounds, Games, Between rounds, Prefabs; it opens on the tab used last) and one entry per kind of scene; only minigames and duels open a second menu. Writing opens directly and offers Prompt starters inside the scene. Between rounds includes an Intro template. Settings such as a quiz's layout (big tiles, a list, true or false), what a scoreboard shows, upload types, drawing blind and who decides a party choice are chosen in the scene's own panel), connected by dragging between ports, with snapping, problem markers per scene, automatic saving and publishing. Several people can edit the same game at once: each sees the others' changes as they are saved, the scenes they have selected and their pointers, and undo/redo only takes back your own steps (you enter with the owner link; people you give editor rights in Admin → People enter with their own personal key). A second tab, the Scene editor, shows the same game slide by slide with a single editable scene canvas with a **Shared screen / Phone** toggle and controls for every setting, including scenes with several parts and team settings. The two have separate jobs: the Flow editor is the map (adding, connecting, moving and deleting scenes, party-choice routes and where each scene leads; its panel shows a summary and **Edit this scene →**, as does double-clicking a card), the Scene editor is the content (questions, answers, parts, points, who plays), where the scene list moves between scenes and the scene’s ☰ menu opens its connections in the Flow editor, routes fold one by one or all at once, right-click a scene in the list to open its actions, and **Try this scene** opens an interactive popup for the current draft. You can try each part of a scene without opening a room. Group rounds use sample players or answers in the popup. The map zooms with the scroll wheel (Shift + scroll moves it) or its zoom menu (*100% ▾*: zoom, show the whole game, zoom to the selection), a *Tips* button lists its gestures, the *Tidy up* menu wraps long games into rows (Ctrl + Shift + L), lays them out in one line, lines up selected scenes and straightens all arrows, arrows run along grid-aligned paths and can get bend points to lead them around something, selected scenes can be grouped (**Group** in the panel, or Ctrl/⌘ + G; a new minigame draw with its games and an inserted prefab are grouped by themselves): click the frame or one of its scenes to select the group, drag the frame to move its scenes together, use **Collapse group** to show it as a **Scene group** card with its external connections, right-click the group and choose **Rename group** or **Group colour** to distinguish it on the map, including a custom colour, Alt-click to select one scene, or press Ctrl/⌘ + Shift + G to ungroup, and **Help & shortcuts** (☰ menu or the ? key) lists every gesture and shortcut. Options with a longer explanation show it behind an ⓘ. On a phone the editor rearranges into short rows, bottom sheets and a scrolling page. The top bar is one compact row: the game name with its state (draft, saved, length, problems), the three editor tabs, Undo and Redo, an **Editing / Viewing** button (Viewing: look through the game without changing anything; remembered in this browser), a **Play & publish ▾** menu (rehearse from the start or the selected scene, publish, play the published version), a ☰ menu with Game settings, Invite people, Export as text, Help & shortcuts and **Light mode / Dark mode** (remembered in this browser, also for the host and admin pages), and at the far right who is editing. Coming back to a game opens the same place: the editor, the selected scene, the open panel and the part of Look & feel (remembered in this browser). Long pages are small named groups that open and close and stay as left: the scene's settings, its parts, Game settings, Look & feel's style page (Style, Colours, Text, Shapes and background, Sliders, Answer marks) and its texts (a search opens the groups with a match). Games can also be imported from text, for example written by an AI assistant: see [Making a game from text](docs/guides/importing-games.md). The instructions the app copies for an AI cover every feature (a test keeps them complete) and make the AI ask a few short questions first (who plays, how long, teams, rounds, style) before it writes the game. The editor can export a game as text too. Drafts can be rehearsed in a practice room without publishing, from the start or from a chosen scene (rehearsing the same game again replaces its open practice room: it keeps the room code, phones, the shared screen and the host tab move over, and the editor reuses the same browser tab); scenes can be duplicated or copied between games, or saved as a prefab (**Save as prefab** on selected scenes; kept in the database, shared by you and your editors) and inserted into any game from the Prefabs tab of Add a scene; a minimap helps in large games. Minigame scenes play on the phones: Reaction duel, Tap race, Stop the clock and Lucky doors (shuffled every game, or fixed as listed), Drive the bus (the Dutch drinking game "bussen" without the final bus: teams guess red or black, higher or lower, inside or outside, then the suit; wrong costs sips) and Left or right (everyone picks in secret; the majority wins), each with settings, points by place (ties share) and team play including one against the rest; a built-in "Minigame madness" game shows all four. Lucky doors, Drive the bus and Left or right are *step games*: one engine plays any game made of choices (a game only brings its rules), and in a team round the scene decides how a team chooses: anyone taps it, the team votes (each member once within the vote time, which the server ends by itself; who does not vote is not counted; a tie goes to the captain or a random pick), or the captain decides (a team without one gets a fixed random captain). Players build their own look (a character from built-in parts: colour, body, eyes, mouth, hat, extra), or use a drawing or a photo (metadata removed; the host can remove it); it shows in the lobby, player list, scoreboard and results, and the phone remembers the character for the next game. Minigame results are checked against the server clock and each phone's measured network delay, the tap race streams its taps (live race bars), and pausing restarts a running minigame with a fresh countdown. Drawing rounds (optionally blind, or finishing a doodle) can be voted on, or, like writing and upload rounds, get points from the host (*Points → The host gives points*: after the answers are shown, the host gives each player or team up to a maximum, or a place); every drawing pad except Draw the graph and Perfect circle has the same toolbox: 16 colours, 4 sizes, an eraser, undo and start over; drawing minigames are Perfect circle and Pass the pencil (teams take turns on one picture, then vote, with every stroke shown live). Drawing also works with the keyboard. Games can have wheels of fortune (spun by the host on chosen scenes, the result kept in a corner of the shared screen; slices in the game's answer colours or the wheel's own, with readable labels, and a **Test spin…** in the editor: click the wheel to turn it, click again while it turns for a boost), players can vote for a smoke break that pauses the game, games end with an awards show the author configures (each award with its own title if wanted; besides the statistics, "best in one scene" and the wooden spoon for the fewest points; swipe or step through the awards; auto-play is a toggle on each screen, on by itself only on the shared screen), every scene that gives points can also pay by place (points for 1st, 2nd, 3rd…, or a total split automatically, evenly, steeply or equally: the fastest correct answers of a quiz or ordering round, the most-voted answers, the host's places in a challenge, a minigame's results), a head-to-head duel scene puts two players (at random or picked by the host) against each other while everyone else bets on the winner (any contest in the room that the host decides, or rock paper scissors, tic-tac-toe or chess on the two phones; the winner, the runner-up and every right bet are paid automatically), and the editor shows about how long a game takes. Old pictures, videos and drawings are deleted automatically after `MEDIA_RETENTION_DAYS` (default 14) once a room is over or unused. A quiz, writing, upload, drawing or challenge round and a cutscene can show a **picture, video or song** with its text (the scene's *Picture, video or song* in the Scene editor). The files come from the **media library**, shared by the owner and editors: upload a PNG, JPEG, WebP or GIF picture (up to 10 MB), an MP4, WebM or MOV video (80 MB) or an MP3, M4A, Ogg, WAV or FLAC song (25 MB), 4 GB in all, stored under `game-media/` in the media folder and never cleaned up by itself; a file a game's draft or latest published version uses cannot be removed. Pictures show on the shared screen and the phones; a video or song plays in one place only, the shared screen (or the host's screen when no shared screen is connected), with a Play button when the browser wants a tap first, and the phones say to watch or listen. **Media placement** and **Media size** update the canvas and the live scene. **Add media** opens the library, where authors can crop a picture or cut a video or song for the scene. **Pause** in the host controls pauses the scene’s video or song, including on a connected display. Use the player on the playback screen to seek or change its volume. Files are played as uploaded (nothing is converted), so keep them small. Text import can reference a YouTube clip. Uploaded library media is chosen in the editor and its references are kept in exports. A game can have **background music**: a playlist of library songs (Game settings → Music) that plays on the shared screen (or the host's screen without one) from the lobby on, song after song and round again. Add and reorder tracks in the editor. A playlist of one repeats. Each scene's *Music* group keeps it, plays a song of its own on repeat (the playlist then continues where it was), plays it quieter, or is silent; under a scene's own video or song the music plays quieter by itself. In the room, Room settings has *Music plays* and a volume slider (standard 60%), carried over to the next room. When the browser blocks sound until a tap, a *Start the music* button appears. Each library file can have a **credit** (composer and licence; set in the media library), and the shared screen names each song with its credit for a few seconds when it starts. **YouTube video scenes:** In a supported scene, open **Picture, video or song → Add media → Add YouTube video**, paste a public embeddable link and optionally enter start and stop times as seconds from the start of the video. YouTube plays in its own player on the shared display, with the host screen as a fallback. Use the player’s Play button if autoplay is blocked, or **Open on YouTube** if the video cannot be embedded. **Standard songs**: `npm run music:defaults` (once per server, after `npm run build`) downloads Kevin MacLeod's “Hotrock”, “At Launch” and “The Show Must Be Go” (incompetech.com, CC BY 4.0, credited) and “Loop 3” by Gichco (OpenGameArt, public domain) into the library, checking each file's SHA-256; the files are never kept in the repository. *Use the standard songs* in Game settings → Music puts them on the playlist. A song that cannot be loaded is skipped. Spotify cannot be used: its developer terms forbid games and trivia quizzes; play Spotify yourself on the shared screen's computer and switch *Music plays* off in the room. **Invite people** (☰ menu at the top right) lists your people: copy an invite link for someone with editor rights (it signs their phone or computer in with their personal key and opens this game), or give editing rights with one tap. Clicking an arrow in the Flow editor opens a small menu to add a scene on it (a wheel, a cutscene, a scoreboard… placed between the two scenes, so it plays right there) or remove the connection. **Wheel of fortune** is a scene type of its own: the scene’s wheel and its entries are edited right in the scene. **Minigame draw** (add menu → Games) picks and plays one minigame in the same scene, with one shared next connection and a pencil for each game’s settings. Choose **Minigame draw with routes** to give each result its own scene and continuation, with the on-screen draw and host selection. **Game settings** (☰ menu at the top right) gathers everything about the whole game: name, start scene, side games & chips (and how many challenge invites a player can have waiting at once: 3 unless changed; the host can change it in the room too), wheels of fortune and end-of-game awards. **Teams** are not a game setting: a game is everyone-for-themselves unless it has a **Pick teams** scene (in the add menu), where the teams are made (a number of teams or exact sizes, at random, by the host or by the players, optionally with captains). Rounds after it can be played in those teams ("Who plays"); only rounds that can be played in teams offer it, and only once the game has a Pick teams scene. The Pick teams scene's *Team names* give the teams their own names (empty: Red, Blue…; more teams get free standard names). Each team has a colour: the host picks any colour for a team (the round button on its column), and with *Team colours chosen by: Teams and host* on the Pick teams scene a team picks one of twelve colours on its phones; a team named after its colour follows the new colour's name. A player's page carries a stripe in the team colour along the top, and their team chip shows only the colour. In the room each team is a coloured column with its players: the host taps a player and then a team (or drags with a mouse), makes captains, adds teams (up to 12) or removes them, shuffles, and starts with the big host button. Games made before this keep working; opening one in the editor turns its game-wide teams into a Pick teams scene at the start. A scene’s own panel groups its settings into Content, Points, Who plays and Where next; each group stays open or closed as you left it when you select another scene (remembered in this browser). Short choices are buttons, choices that need a description (which minigame, how a duel is won, an award to add) open a popup with cards, lists (scenes, wheels, fonts, animations) use the editor’s own keyboard-friendly dropdown, and the scene’s actions (start here, duplicate, save as prefab, delete) are in the ☰ menu next to Close. Delete or Backspace on selected scenes asks before deleting. A third editor tab, Look & feel, changes how the game looks and talks: every text players and screens show, a style (presets including ASCII Terminal, Space, Christmas, Birthday and MBO Utrecht's colours, then any colour (with the app's own colour picker: a shade square, hue and opacity sliders, the code as hex or RGBA, typed or pasted, the look's colours for reuse and a screen eyedropper in Chrome and Edge; see-through colours are kept as `#rrggbbaa`), font, size, roundness, background and answer-tile style, an optional gradient effect on tiles and buttons, and the answer marks (A B C, 1 2 3, shapes, your own typed marks or none; their shape and place; arrows or the same marks on party choices), with readability warnings; colour palettes can be imported from Canva, Figma, Coolors or Adobe and exported for them: hex codes, a Coolors link, CSS, design tokens or an .ase/.gpl file) and the animation for each moment (sixteen ready-made, or built from blocks; each shown on a timeline and in words), for the whole game or a single scene. Under Look & feel → Colours & style → Sliders, choose Blade (the default), Notch, Ring, or Dial for Cut the Line. Under *Timer*, the time left shows as numbers or as a round clock whose coloured slice runs out (clockwise or counter-clockwise), pulsing red in the last seconds and flashing red when time is up. The clock can have its own colours (*Clock colours*: the clock's rim, the time left and the last seconds; standard: the look's text, accent and danger colours). Built-in styles never change: changing one makes a new style of yours; your own styles ask whether to update them or save a new one. The styles are grouped (Yours, Everyday, Bold, Space & sea, Occasions, Brands), and the preview opens on *This scene*. A scene can inherit the game’s slider or choose its own. Looks are data only, validated by the server; authors never write code or CSS. Built-in games are "Friday Night Chaos" (a route vote), "Timed quiz", "Team party", "Minigame madness", "Bar games" (Drive the bus with team votes, then Left or right), "Draw party", "Picture party" (uploads and a vote) and the untimed "First reliable game".

On an eligible development server bound to loopback with a loopback public origin, the join screen offers **Sign in as owner**. It signs you in without a key before opening the host menu. Serving over a public origin or tunnel uses the private owner link.

Signed in as the owner, the host menu, the editor and the admin pages show a top bar: Play, Host, Editor and the Owner menu. **Editor** opens the last game edited in this browser; until a game has been opened it is gray. The host menu lists *Your games* (with **+ New game**, **Import from text** and **Copy AI instructions**) and, under them, the built-in games, each with **Open room** (and, for the owner, **Edit**). People with a role see Play, Editor and Host (called *Games* when their role may not host real rooms). Server replies determine which navigation the browser shows. The start page offers **Host a game instead** to verified owners and **Edit games** to verified editors. Protected links return to the start page if access is denied. Open **Help & shortcuts** to change the two map zoom shortcuts. On the flow background, Shift-, Ctrl-, or Command-drag selects several scenes. **Scene actions → Replace scene type** starts the selected scene with the new type’s defaults and supports Undo. Incoming connections and a single outgoing connection stay connected. If a vote depends on a part that would disappear, or several outgoing routes would be lost, the editor asks you to resolve those links first.

**Group 5 games and room tools.** Speed run is available as a minigame scene and in Arcade. The scene can use the stock route or a custom obstacle grid. Pass the pencil can play in animation mode, with private prompts, separate frames and a team guessing round. Creature duel supports one creature per side or teams of three in Duel scenes and private phone challenges. The host can enable room, team and private chat in Room settings. Chat moderation includes reports and mutes. Final scoreboards show player reactions and public chat messages selected by the host. Players can test the microphone in Menu → Phone effects before the game. The game’s Host tools can also enable lobby choices for score sounds and effects.

**Brick Rally** is a brick breaker with 32-by-24 maps of small, square bricks. The ball chips away at the edge it touches, and you can set tough bricks to take two to nine hits each. The **oudje** preset spells “Menno is oud!” Break a Split Ball brick to add another ball (up to three), or a Wide Paddle brick for eight seconds of extra paddle width. In **Arcade → Play Brick Rally solo**, pick a preset or paint a custom map, choose a timer and optionally limit lives, then play on your own phone. For a race, choose Brick Rally in an Arcade lobby or add it as a hosted minigame scene. Everyone plays the same map on their own screen, and the fastest verified clear wins. Set the round time, map and lives in the Arcade game settings or the scene’s **Configure minigame**. Lives are unlimited by default. With a limit, losing the last ball on the board spends a life. In a room that allows side games, open **Menu → Challenge → Brick Rally** for a two-player race. Choose a player by their avatar, browse the map previews to pick a preset, and set the timer and lives. Both players tap **Ready to race** for a shared countdown. The default race lasts two minutes.

**Clap the beat** is available as a minigame scene and in Arcade. Players can tap each lit cue or opt in to local microphone detection. The phone sends the score and releases the microphone when play ends or the page is hidden. **Pick teams** offers **By skill**, and the host can rebalance a proposal using revealed individual scores while keeping team sizes. The editor remembers saved undo and redo history in this browser, offers remapping under **Help & shortcuts**, and can style media, ballots, minigame controls and other game moments under **Look & feel → Animations**.

**Cut the Line** is available as a minigame scene, in editor practice, and in Arcade. Players get the same random target and use an unmarked bar that moves in tenths of a percent, so there are no whole steps to count. The round gives players 20 seconds after the countdown by default. The server ranks locked cuts by distance from the target, with equal distances sharing a place and its points.

**Match the Angle** is available in those same places. Players drag a ray in tenths of a degree (no whole-degree steps to count) toward a shared target and lock in before time runs out (20 seconds by default). The closest angle wins, including across 0°. The server uses the earlier submission to break equal-distance ties.

**Count the Dots** is a hosted minigame scene. The host and shared display show the same random pattern of non-overlapping dots. Phones get a number field as soon as the dots appear and can still submit after the dots disappear. Set **Dot viewing time** (5 seconds by default) and **Guessing time** (15 seconds by default) in the scene editor. **Dot count** accepts an exact count or a random range from 1 to 500. Standard random rounds use 50–500 dots. The reveal shows the actual count and ranks guesses by distance, with the earliest submission breaking ties. Phones show the actual count, their own guess and how far off they were. Try the sequence in the editor’s shared-screen preview.

**Heads or Tails** is a hosted minigame scene. Each player secretly picks a side on their phone. The host and shared display animate the same coin flip when guesses close (or, with *The coin flips: When the host flips* under **Configure minigame**, when the host taps **Flip the coin**), and every correct guess earns the configured **Points per correct guess**. The guessing timer defaults to 15 seconds.

**Drive the bus** is a team drinking game: each team guesses red or black, higher or lower, inside or outside, then the suit; a wrong guess costs everyone in the team that round's sips. When the first three cards are three different suits, round 4 also offers **Rainbow**: right, the other teams drink the last round's sips; wrong, the team drinks them. A rainbow only counts when it is called (the *Rainbow rule* setting can switch it off).

**Roulette** is one European roulette table used everywhere: as a hosted minigame scene, in the arcade and as a solo phone side game. Bets can go on any number 0–36, red or black, odd or even, 1–18 or 19–36, a dozen or a column. A number pays 35 to 1, a dozen or column 2 to 1, and the other bets 1 to 1. A winning bet also returns its stake and a losing bet is lost. Green zero loses every bet except a bet on 0. On the wheel, a ball rolls around the rim against the wheel's turn, drops, bounces and settles in the winning pocket. In a hosted or arcade round, players bet their own points privately and the ball rolls once for everyone when betting closes. A player may bet up to their score, or up to the scene's minimum stake (100 points by default) when their score is lower, so a loss can take a score below 0. A single free pick with no stake is also allowed. On a phone, open **Menu → Games → Roulette** to play the same table with play chips, or free when chips are off.

**Team captains.** A Pick teams scene with captains (and a round with its own teams where one captain answers) has *Captains: Assigned / Elected* in the editor. Assigned: the host taps a player and **Make … captain**, otherwise each team gets one at random. Elected: while teams are made, each player taps a teammate on their phone to vote (not themselves; they can change it), and everyone sees the votes and 👑 on the leader. When the host starts the round the host's own pick wins, then the most votes; a tie is drawn. The host can switch between Assigned and Elected above the team columns. In minigames played by captains, teammates see their captain's answer in their own result. Draw the Graph, Heads or Tails, Roulette and Undercover are always played individually.

**Team scores when teams are made again.** A later Pick teams scene (or a round that re-picks the game's teams) has *Team scores* in the editor: *Start from zero*, *Keep each team’s score*, *Add up the members’ scores*, *Share out the old team scores* or *The host types the scores*. **Share out** divides each old team's score equally over its members (rounded down to a thousandth of a point); each new team then starts with the shares of its members. With **host types**, every team column on the host's screen gets a *Points … starts with* field. With either rule, every screen shows *Starts with … points* per team before the host starts the round. While the room's scores are secret, phones and the shared screen do not see these totals. The start is fixed when the host confirms the teams. A later re-pick replaces it, so the same points are never added twice. Players' own scores never change. The end show's **Winning team** award (`teamWinner`, on by default) shows the game's team with the most team points, its colour, members and points. If teams tie, or there are no teams, the award is left out.

**Checking answers after the reveal.** On a revealed quiz or ordering round the host has **Check the answers (n)** under the results. It lists each answer with who gave it, what they answered and whether it was right. **Count as correct** gives a wrong answer what a right answer earns in that round, without the speed places. **Not correct** takes a right answer's points away. **Undo** goes back to the round's own scoring. The player's phone says *The host counted your answer as correct* (or not), and the round's points, the totals, team scores, the end-show awards and people's right/wrong statistics all follow. Applying the same verdict twice is refused. Every verdict and point change is kept, linked to the answer. The free **Correct score** on the scoreboard is still there for anything else.

**Galgje (Hangman)** is a minigame scene (editor group *Words*) and an arcade game. Everyone, or every team, guesses the same secret word letter by letter on a letter keyboard; each wrong letter draws more of the gallows. **Guess the word** under the letters lets a side name the whole word at any time: the right word solves it at once, a wrong one costs a life like a wrong letter (and is listed with the wrong letters; the same word twice is refused). In a team vote, a word counts as one more choice. Fewest wrong guesses wins, ties go to the fastest, and a side that is hanged gets no place. Only your own phone (or your team's phones) shows your letters; the shared screen shows each side's gallows and how many letters it found, and the word itself at the reveal. Set the wrong letters allowed and your own words (one per line), or use the built-in words in English, Dutch, German or Romanian.

**Undercover / Mr. White** is a minigame scene (editor group *Words*) and an arcade game for at least 3 players. Each phone shows its own secret word after a tap: most players share one, the undercover players have a similar one, and Mr. White (from 5 players) has none. In turns, everyone says one clue out loud and taps *I gave my clue*; then everyone votes someone out on their phone. The player with the most votes is out and their role shows. A tie goes to one **re-vote** between the tied players (everyone still in votes again, only for one of them; the tied players are marked); a tie in the re-vote sends nobody out. A voted-out Mr. White may type the word and wins alone when right. The civilians win when every impostor is out, the impostors when they are as many as the civilians. The host can skip a turn or count the votes at any time; once the time is up, any player can. It is always played alone, also in a team game. Set the number of undercover players, Mr. White, the time per clue and per vote, and your own word pairs (or built-in pairs in four languages).

**Your own words as host.** In Room settings, *Your words (Galgje, Undercover)* takes Galgje words (one per line) and Undercover pairs (`zon, maan`, the civilians' word first). Every Galgje or Undercover round that starts afterwards in that room uses them instead of the game's own words; only the host sees them. *Use the game's words again* clears them.

**Own reactions and the soundboard.** In the editor, *Game settings → Reactions & sounds* adds the game's own reactions (an emoji, a short text, or a picture or GIF from the media library) and its soundboard (built-in sounds such as fanfare, air horn and drum roll, plus sounds from the media library). On a phone, the reaction button opens *React* and *Sounds*. A sound plays on the shared screen (or the host's screen without one), one at a time, with 20 seconds between two sounds of the same player. The host switches the soundboard off in Room settings (*Players can play sounds*).

**Who sees which game.** The owner sees every game in *Your games*, with *by …* under games an editor made. An editor sees only the games they made and the games shared with them. To share a game, open it in the editor, then ☰ → *Invite people* → *Who can edit this game*, and tick the editors (the game's maker or the owner can do this). The owner can also set *Made by*: games from before this was kept count as the owner's. Copying a person's invite link there also shares the game with them.

**Team celebrations.** While teams are made, each team taps *🎉 Our celebration* on its phone: an emoji, a short cheer and a sound from the game's soundboard. The last tile of the emoji and of the sounds is a **+**: type or paste the team's own emoji, or upload the team's own sound (a short file or phone recording, up to 2 MB, played for 6 seconds at most; MP3, M4A, Ogg, WAV, FLAC or a recorder's MP4/WebM, recognised by its bytes). The tile then shows the team's own choice, and tapping it again replaces it. Only a member of that team can use the team's uploaded sound. The sheet fits one phone screen. When the team wins a round (the most team points) or the game, the shared screen (or the host's screen without one) shows *Red wins!* with the cheer and falling emoji and plays the sound; the team's own phones show it too.

**Admin: live rooms, storage and the action log.** In the owner's menu (top right): *Live rooms* lists every open room, with *Open as host* and *Close room* (its answers and scores stay); *Storage* shows free disk space and what the server keeps, with *Clean up now*; *Action log* lists what you and the editors changed, newest first; *Health* shows how the server is doing (database, room updates, errors, disk and memory), each part with OK, worth a look or a problem.

**Media extras.** A scene's picture can have a description for screen readers, and any scene media a caption shown under it on every screen. With a shared screen connected, the host has *Play*, *Pause* and *From the start* for the scene's video, song or YouTube clip on that screen. The playlist can shuffle and fade between songs (Game settings → Music). The shared screen plays short event sounds (the last five seconds, the end of a round, the reveal, the winner); switch them off in Room settings.

**Minigame Tryout** opens from the menu bar on the local Host page. Choose any hosted minigame and click **Play selected**, or click **Replay** to start a fresh attempt with the same players. It uses the standard game settings and the real phone, host, timer, and scoring flows. Team games use two teams and let the host confirm the lineup. **8-ball pool** goes straight to the table. Choose **Free play** to take both sides on one phone with the same pool rules, or use **Play selected** with two phones for a match. Use **Landscape** above either virtual phone to change its orientation without rejoining. Use **Ball behavior** to compare the three cloth presets or tune a custom table.

**Draw the Graph** is a hosted round. Players see the scene’s question and the same partial chart, with their own line color and a live period and value readout. At reveal, the actual continuation and all submitted guesses draw together from left to right on the host and shared screens, followed by the rankings. The host can replay, pause, resume, or show all lines on both screens. Lowest average vertical error wins, with submission time breaking ties. Each phone shows its own prediction over the actual line and its own points. In the Scene editor, choose **Import graph data** to paste an [Our World in Data chart link](docs/product/graph-data-sources.md), upload a CSV, or paste spreadsheet data. Review the imported chart, select a series, and drag the divider to set the last period players can see, then choose **Use this data** and **Apply changes**. **Import all new series** also saves the other series to the graph library. Open **Game menu → Graph library** to import directly or browse and edit charts from the game drafts you can access. Click the graph’s row or its eye button to preview or practice, or choose **Edit** or **Delete**. Deleting a chart attached to a scene restores its sample graph. Changes are saved to the source draft. In the import review or graph editor, choose **Preview** to see the graph on a phone or shared screen and play a practice round before saving. Drag the divider again to change the cutoff, or open **Edit data and axis labels** to change the readings, axis labels or source credit. The editor also supports the built-in chart and manually entered values. Stop the Clock hides the round’s time-left badge. See the [minigame playtest checklist](docs/product/minigame-playtest.md) for the tuning queue.

**Phone previews.** Every phone in the editor (the Scene editor, **Try this scene**, a minigame's settings and Look & feel) is drawn as a real phone: the chosen model's proportions, its camera cutout and home bar, at its real width where there is room and smaller (never stretched or cut off) where there is not. Choose the model next to **Shared screen / Phone** in the Scene editor, or above the phone elsewhere: iPhone 16 / 15, iPhone 16 Pro Max, iPhone 14 / 13 (the standard), iPhone SE, Samsung Galaxy S24, S24 Ultra and A15 / A25, and Google Pixel 8 / 9. The choice is remembered in this browser and also sets the size of the test bench's phones. The picker stays visible and the preview keeps the selected model’s native logical dimensions and aspect ratio on small screens, scaling the whole phone uniformly to fit. **Play & publish → Test bench** rehearses the draft from the start on the test bench (the host screen with up to four virtual phones in one tab).

**Right-click menus.** In the Flow editor, right-click a scene for its actions (Open, Start here, Duplicate, Copy, Paste, Replace scene type, Save as prefab, Delete); with several selected they act on all of them, with Group or Ungroup. Right-click an arrow to add a scene on it, straighten it or remove it. The menu key or Shift + F10 opens it on a focused scene; right-click on empty map still adds a scene there.

**Scenes with their own look.** In Look & feel, scenes that have their own look carry an *Own look* tag in *Change the look of*. While styling the whole game, the *This scene* preview says when the scene shown ignores the game's look, with *Edit this scene's look* and *Use the game's look*; *Use the game's look everywhere* (after asking) makes every scene follow the game again, in one undo step.

**Save points.** The editor saves every change by itself; a save point is a copy of the whole game kept on the server to go back to later, for example before a big change. Open **☰ → Save points** (or press Ctrl/⌘ + S), name it and select **Make a save point**. The list shows when each was made, how many scenes it has and who made it; the owner and editors of the game share them. **Go back** first keeps the game as it is now as the save point **Before going back**, but only when it holds changes no save point has (one such copy at a time, replaced by the next), so going back and forth never piles up save points; then it makes the game what it was. Undo also takes that back, and the published version only changes when you publish again. A game keeps up to 60 save points; the ones you made stay until you delete them.

**Custom fonts.** In **Look & feel → Colours & style → Text**, upload a WOFF2, WOFF, TTF or OTF file up to 10 MB, or paste a Google Fonts specimen, share or stylesheet link for one family to import its regular font. The shared font library is available to the owner and editors. Adding the same file again brings up the existing font. Open **Shared fonts** to remove a font. A font used by the current look, a game draft, a game's latest published version, a saved prefab or a saved style can't be removed. Select body and title fonts for **The whole game**, or choose a scene to override either one. The host, players and shared screen load the selected fonts from the game server.

**Your own styles.** In **Look & feel → Colours & style → Style**, **Save as new style** keeps the current look under a name; saved styles appear above the built-in ones for the owner and editors in every game, each with a red delete button. When the look is exactly a style and you change something, a popup asks first: **Create new style** (based on it, named), **Update** the saved style (own styles only), **Only change this look**, or **Cancel**. The answer holds until another style is picked, and a style created or updated this way keeps following your next changes. A game keeps its own copy of a style's values, so updating or deleting a saved style does not change games that already use it.

**Phone menu icons** use monochrome line art by default. Open **Look & feel → Phone menu** to change individual icons for the whole game, including each entry in the side-game picker. The menu footer groups **Settings**, **Language** and **Leave room**. The reaction icon beside Menu opens the reaction tray directly when enabled. Settings contains sound and available phone effects. Leave room is red and asks for confirmation.

**8-ball pool.** Players can use **Menu → Challenge** for a phone match with optional play chips. Add a hosted round using **Add a scene → Minigame → Other → 8-ball pool** or choose it as a Duel. A random or host-picked pair plays after the other players predict the winner. The winner and correct predictions earn configurable points. **Configure 8-ball pool** groups matchmaking and timers under **Match**, cloth and break placement under **Table**, and awards under **Points**. **Add Pick teams scene** inserts team setup before the pool scene on every incoming path. **Team vs team** uses the current game teams and draws one player each from two distinct teams. This mode starts without voting and awards only team points. The shooter’s phone starts the ball motion locally while the server confirms the shot. Ball hits and cushion rebounds play distinct sounds when device audio is enabled. The table has a grained wooden rail with sight diamonds, a cloth with a fine weave, cushions whose angled jaws stop at each pocket, and pocket holes with a rim set into the rail (drawn once per cloth and reused each frame). A ball drops only once more than half of it is over the edge of the cloth, so one that only grazes a pocket rolls on; each jaw is a small rounded nose, so a ball caught on the edge of a pocket is thrown back out. Aiming works in hundredths of a degree (the aim wheel turns smoothly), the power bar shows a whole cue drawn back, and **Swap** puts the power bar and the aim wheel on the other sides (remembered per phone). In a duel the room names the winner once (and who gave up); the replay opens with **Watch the replay**. Under **Table**, **Table cloth** picks green (default), blue, teal, red, purple or gray, shown in the preview and on every phone, host, TV and replay. Potted balls slide into the pockets and shrink as they drop, and each player’s tray shows the numbered balls they potted during the match on the phones, host and TV. The TV link fills the available screen with the table. Set **Match time** to start a separate countdown after voting. At expiry, legal pots after the break decide. If both sides are on the 8, fewer cue-ball scratches wins. The host can pick the winner or skip a remaining tie. Drag on the table to turn the aim, or tap a spot to point straight at it. Roll the ridged wheel on the right of the table for quarter-degree adjustments. Pull the cue down the power bar on the left and let go to shoot; a tiny pull cancels. You can also grab the cue stick on the table, pull it back, and release, or press **Shoot** to use the last power. A see-through ghost cue ball marks where the cue ball meets the object ball, and a short line shows where it comes off a cushion. Pocket openings have no cushion: a ball runs into the pocket unless it clips a jaw tip. A cue ball that has rolled a while follows through after contact, while follow and draw from the tip fade with distance. The break hits harder than later shots so the rack opens up. **Time per shot** under **Match** (off, 15, 30 (default), 45 or 60 seconds) puts a countdown bar on the shooter's tray. When it runs out the turn passes with ball in hand behind the line, or on the break the other player breaks. While one player lines up, the other player's phone, the host screen and the TV show their cue and aim line see-through, live. Aim positions are relayed, never stored. **Aim assist** toggles the projected paths after contact on your phone. A gold ring marks the balls you can hit first. **Spin** selects where the cue strikes the cue ball for follow, draw, or sidespin. Phones support landscape play. The **Rotate table** button requests a native landscape lock in fullscreen and can turn the pool view sideways on its own when the browser declines. The break leaves the table open. If the 8 drops on the break, it returns to the table. The first legal pot after the break assigns solids and stripes. The starting line marks the break area. Use **Starting side** and **Starting line** to choose left, right or a side drawn at random each match, and set the distance from that edge. After a foul, the cue ball must be placed behind that line. Sink the 8 in the pocket opposite your last ball. Sinking the 8 early, in the wrong pocket, or with a scratch is a loss.

## Importing and trimming music

Open **Game menu → Media library** from any editor tab to browse and manage the shared pictures, videos and songs. Besides the kind of file, the library can be narrowed to the files of one game (*All games*, *This game*, another game, or *Not in any game*); each file says which games use it, counting a game's draft and its latest published version.

In a game's editor, open **Game settings → Music → Add a song → Import from YouTube**. Paste a public video link for audio you have permission to download and use, then name the track. The editor saves the MP3 in the shared media library. Select **Trim** on any library song, choose the start and end in seconds, preview the cut and select **Save MP3 copy**. Then choose **Use this** to add the track to the playlist. The same library is available from a scene's **Music** and **Picture, video or song** controls.

Audio processing runs on the server. Install [FFmpeg](https://ffmpeg.org/download.html) with the MP3 encoder (libmp3lame), and install a current [yt-dlp](https://github.com/yt-dlp/yt-dlp#installation) with its JavaScript challenge solver (for example, `pipx install 'yt-dlp[default]'`). The server looks in the project's ignored `.local/tools/audio/` directory first and then on its PATH. YouTube import also needs internet access on the server and accepts individual public videos up to 20 minutes. Library tracks and clips use the existing 25 MB audio limit. Clips keep the source's credit, which you can edit in the library.

Songs attached directly to a scene have a player with play and pause, seeking, volume, and a waveform when the browser can read it. Use **Show waveform** in the scene’s media settings to control its visibility.

## Package boundaries

- `apps/web`: React/Vite browser UI; presentation only.
- `apps/server`: Fastify API, authentication enforcement, logs and instrumentation.
- `packages/contracts`: public runtime schemas/types; no secrets or privileged engine code.

## Instructions: test version, feedback, people and side games

Step by step for the owner. Starting, checking and stopping everything is in [Running the party game](docs/guides/running.md).

### 1. Put out a test version for other people

1. Once: `npm ci`, `npm run db:env`, `npm run db:up`. After pulling new code, every time: `npm run db:migrate:deploy` (it only adds what is new).
2. `npm run build`, then `npm run network:public`. It prints `PUBLIC ADDRESS: https://….trycloudflare.com` and opens the host menu, signed in as you.
3. Testers open that address on their phone or computer. Players join a room with the room code or the QR code.
4. The address changes every time the test link starts. Send the new one each time. Lost the host tab? `npm run host:link`.

### 2. Feedback: bugs, wishes and minigame ideas

For testers (no account needed):

1. Tap **Feedback**: on the right edge of the screen, or in the top bar on the host menu, the editor and the admin pages.
2. Choose *Something is broken*, *Idea or wish* or *Minigame idea*, and give it a title (and details if you like).
3. Optional: **Point at something**, then tap the thing on the screen you mean. The tap picks it instead of pressing it. Up to five things.
4. Optional: your name (the phone remembers it). **Send**. Keep the report ID from the confirmation if you want to follow up with the organiser.

For you: open **Owner → Feedback reports** in the top bar (`/?admin`).

- Filter by kind or status (open, all, new, planned, in progress, done, declined). Search by report ID or text.
- Change a report's status or kind, write a note, or delete it.
- **Mark N as done** marks everything the filters show (kind, status and search) as Done at once, after a confirmation. Only bugs selected: only the bugs change.
- **Copy as text** (one report) or **Copy N as text** (everything shown) includes each report ID, the screen, the page and, for each pointed-at thing, the file and line in the code (for example `JoinScreen in apps/web/src/room/room-screen.tsx:38`). Paste that into a request to fix it.

What a report keeps: the page address without the part after `#` (so never a key), the screen (player phone, host screen, shared screen, editor…), its size, the browser, and for each pointed-at thing its text, where it sits in the page and its file and line. Nothing typed into the game. The file and line come from the build, which writes them onto every element (`apps/web/tooling/source-tags.ts`, about 2% more download; `PARTY_SOURCE_TAGS=off npm run build` leaves them out). Limits: 30 reports a minute and 200 an hour per address (testers coming in through a Cloudflare tunnel count as one address unless `TRUST_CLOUDFLARE_LOCAL=true`, see `.env.example`), at most 5000 unhandled reports, no screenshots.

Feedback can include one PNG, JPEG or WebP image up to 2 MB, or one MP4, WebM or MOV clip up to 5 MB. Attachments are kept with the report in PostgreSQL and can only be opened in Admin by the owner. Deleting the report deletes its attachment.

### 3. People: accounts so you are always yourself

1. Top bar → **Owner → People** (`/?admin=people`).
2. Type a name (for example *Dinny*). Tick **Can edit games** for someone who should help make games (see below). **Add person**. Their personal key (like `K7QM-4XPT-9RWD`), a personal link and its QR code appear.
3. On that person's phone: on the start page tap **Have a personal key? Sign in** and type the key (capitals, spaces and dashes do not matter), or scan the QR code / open the link. The phone says "This phone now plays as Dinny".
4. From then on that phone joins every room as Dinny: the name is filled in, the character comes back, and the chips carry over between games. Joining the same room from a second phone of the same person continues the same seat. A new phone signs in with the same key.
5. On a phone, **Not Dinny?** on the join screen signs that phone out.

The owner’s People list shows the **Personal key** next to each person. Select the key to copy it or share a sign-in link or QR code. A name opens that person's own page: their stats (games, wins, top 3, points, right and wrong answers, minigames, challenges per game and their main rival, arcade, side games, chips, favourite and last game, each with their rank), **Can edit games**, **Share key** / **New key** (the old key and link stop working; phones already signed in stay signed in) / **Sign out phones** (all of that person's phones become guests), **Rename** and **Remove** (signs out, stops the key, frees the name; past games and chips stay in the history). In **People → Groups**, make a group, open **Add people** or **Edit members**, and check the names to include, or use **Add everyone** / **Add all N found** (and **Remove…**) to take everyone matching the search at once, also those on other pages (a group holds at most 500 people). Changes save automatically. Someone can be in any number of groups. In a room, *Add people…* in the Players sheet lists the groups first: ticking one adds all its members to the room's list, unticking takes them off again (half-ticked when only some are on it). Deleting a group keeps its people; removed people drop out of their groups. The **Leaderboard** tab ranks everyone: titles with the top three each (Champion, Brainiac, Confidently wrong, Sharpshooter, Never misses a party, Arcade king, Duel master, High roller) and a table that sorts by any column. Every list of people (the People list, a group's members, a room's *Add people…*, the editor's *Invite people*, the leaderboard) comes 50 at a time with page buttons, and searching (ignoring capitals and accents: “anouk” finds “Anoúk”) happens on the server, so all of them work however many people there are; the numbers at the top and the ranks count everyone. Stats count finished real games only (never practice rooms); an answer the captain gives for a team counts for every member of that team (not for players who sat out). People made before keys existed show no key until you make a new one; their old links keep working.

Without a key at hand, in a room:

- **Players can make an account when joining** (Room settings, off by default): the join screen then offers *Make me an account*; the phone becomes that new person and shows their personal key once, to write down (you can look it up in People).
- **People you added** (the host's Players sheet → *Add people…*): tick people who played before. Their key shows next to their name (to tell them in person) with whether they are in the room. On the join screen they see *Played with us before?* with those names; tapping one asks you (*A phone says it is Anouk: Yes / No*), and once you say yes that phone is signed in as them for good. Only the phone that asked gets it, once. The list and the setting carry over to *Back to lobby*.

Roles: **Admin → Roles** lists the roles and what each may do. Every server starts with **Editor** (make games, manage the media library, test bench and tryout; on a shared game: look, change, publish, save points, rehearse, copy) and **Viewer** (on a shared game: look, rehearse, copy). You can change both, and add your own roles (for example a *Quizmaster* who may host real rooms). App permissions are: make games, see and edit every game, manage the media library, test bench and minigame tryout, and host real rooms. Game permissions apply to a game shared with that person: look, change, publish, save points, rehearse, copy, share with others and remove. Whoever made a game may always do everything with it. Under **People** each person gets a role, or none (a player only). In the editor's **☰ → Invite people** you choose each person's role for that game. A person with a role gets an **Edit games** link on the start page once signed in (or opens `/?host=1`). Without *Change the game* the editor opens read-only with a **View only** label. The server checks every permission on every request; the buttons only follow it. The admin menu stays the owner's alone. Changing a role, giving a person another role, signing their phones out or removing them takes effect at once, including an editor they have open. A role cannot be removed while people or shared games use it. Editing uses the same owner access as hosting, so it only works where the owner link works (never in production).

Good to know:

- The key works like a password you can look up: anyone with it can become that person (and, for an editor, edit your games). Give it only to them, and make a new one if it got out.
- The server checks keys by their hash. So you can look a key up, it is also stored encrypted with a key derived from `ROOM_TOKEN_SECRET`: a copy of the database alone does not reveal keys, but the database together with `.env` does. Changing `ROOM_TOKEN_SECRET` makes existing keys unviewable (they still work; make new ones to see them).
- Typing keys is limited to 20 tries a minute per address (behind a Cloudflare tunnel, set `TRUST_CLOUDFLARE_LOCAL=true` so that is per visitor).
- A phone's sign-in belongs to one address. On a new address (such as a new temporary test link) people sign in again with their key.
- Players without a personal key still join as guests by typing a name (or make an account, or pick their name, as above).

### 4. Side games on the phones

Players play on their own phone while waiting: in the lobby, between rounds, after answering, during a break.

- **Menu** button → **Games**: **Slot machine**, **Blackjack**, **Heads or Tails**, **Roulette**, **Packs** (open packs, collect 15 items in four rarities) and the **Leaderboard**. The first visit opens the game picker. Reopening Games in the same room returns to the last selected game. Drag the handle up to make more room or tap it to toggle the sheet height. Roulette is the same table as the hosted round, with play chips as stakes. Drag a pack’s seal to open it, or use Enter on the pack. Solo Heads or Tails can be played free or with a stake when chips are enabled. A correct guess returns the stake plus the same number of chips. An incorrect guess loses the stake.
- **Menu** button → **Challenge**: challenge another player in the room to rock paper scissors, tic-tac-toe, chess, creature duel, 8-ball pool or Brick Rally, for fun or for a stake in chips. Before sending, pick a win target in rock paper scissors, a team size in creature duel, a map in Brick Rally, or use **Game settings** in 8-ball to choose the cloth, cue-ball start, ball behavior and shot clock. The challenged player sees a banner at the top of their phone (Open or Later), no menu needed (each puts it in, the winner takes both, a draw gives it back). The invite shows the selected settings before the other player accepts or declines. Moves arrive on both phones at once. Once a game is over, both can watch the replay and save it as a video on their phone. Challenges, their games and replays are deleted when the room ends (a stake still in play goes back). Chess rules come from chess.js on the server; phones get the legal moves from it. Head-to-head games are plug-ins (apps/server/src/head-to-head), shared with the duel scene.
- Chips are play money only. Everyone starts with 200 (the owner sets this in **Admin → Chips & packs**) and earns more by playing: per point, for 1st, 2nd and 3rd place, a little for taking part, and for winning a minigame, duel or arcade round. There are no free refills.
- People (accounts) keep their chips across games; guests' chips are for that room only.
- The leaderboard shows this room and all time (people only): bet in total, net result, chips now, best win.
- **Pausing**: as soon as a round needs the player (a question to answer, a vote, a minigame, picking teams), the side game closes with "Round started: your side game is paused" and the button says *Games paused*. An unfinished blackjack hand waits until the next time. The server refuses side-game moves while the player is needed, so this cannot be skipped.
- Side games are **on** in a new room and chips are **off**. Players can open packs free from **Menu → Games → Packs**. Only pack openings that spend chips add cards to a collection. **Admin → Chips & packs** controls which sets are available. Chips are an extra: with them on, players bet chips, stake them in challenges and get the leaderboard. A game can change both (editor → Game settings → *Side games & chips*, or `"sideGames": false` / `"chips": true` in an imported game), and the host can switch both at any time with the *Side games* and *Chips* switches in the host panel, in the lobby and during the game. Rooms opened before this change keep both on.
- What pays and the chances are shown in each game. The slot machine pays back about 94 of every 100 chips bet, blackjack pays 3 to 2 for a blackjack (dealer stands on 17, doubling on the first two cards, no splitting), packs never pay chips back. The server draws every card, reel and pack.

**Language of the app's own screens:** the *Language* choice in the header (and in the editor's logo menu) switches the host menu, the host's room controls and the whole editor (Flow map, Scene editor, scene settings, Look & feel, Game settings, help) between English, Nederlands, Deutsch and Română, remembered in that browser (it starts from the browser's language). The admin pages and the problem descriptions stay English. Each part keeps its translations next to its code in a `*.text.ts` file; a test fails when a language misses a text or a placeholder. **On the phones**, each player chooses a language too (on the join screen, and later under Menu → 🌐), starting from the phone's own language. The game's standard texts follow it (all 147, with the minigames' explanations); authors can provide translations of each scene’s question, choices, title and explanation in **Scene editor → Translations**, and of custom interface text in **Look & feel → Texts**. Fields without translations use the original. Drawing and minigame controls and the character builder also follow the browser language. The shared screen follows its own browser's language. **Background motion** is under **Look & feel → Shapes and background**, with Starlight and Light lines options, also available under **Admin → Join screen** for the site-wide join theme. Devices that request reduced motion show a static background.

### 5. Arcade: minigames with friends, without a host or a game

Set an optional **Lobby password** when opening an Arcade lobby, or change it later from the leader’s lobby controls. New players need it to join. Members returning to the lobby keep access. Share the password separately from the link.

Anyone can play minigames and head-to-head games together outside a hosted game. Open **Arcade** from the start page (or `/?arcade`). The arcade wears the same look as the join screen (chosen by the owner in admin): its pages and its rounds.

The lobby is laid out like a party game's phone lobby: a short bar with the lobby name and three buttons (the stacked avatars open **Players**, the person-plus opens **Invite players** with the QR code and link, the gear opens **Lobby settings**: lock, password, leave). Below it one **Next round** card and the rounds played so far, newest first: each card shows a round's top three (with your own place); swipe (or use the arrows) to go back through earlier rounds, up to the last 20, and **Scores** opens the full results of the round shown and the lobby's total; the one action (**Play …** for the leader, *Waiting for … to start* for the others) is pinned at the bottom.

1. Type your name (a phone signed in with a personal key plays as that person) and **Open a lobby**. You are its *leader*.
2. Invite people with the lobby's link or QR code (**Invite players**), or they find the lobby under **Open lobbies** on the arcade page and tap **Join**.
3. The lobby is open by default. The leader turns on **Lock the lobby** in **Lobby settings**: nobody new can join, but players who were in it can always come back. Turning it off opens it again.
4. The leader taps the game tile (**Change**) and picks a game from the **Minigames** or **Head-to-head** grid, then **Alone** or **In teams** (which opens how many teams and how they are made). **Game settings** under the tile opens that game's own settings: the round time and the game's main settings (reaction waits, tap race and drawing time, the stop-the-clock target and when it vanishes, a fixed or random Cut the Line target or dot count, lucky doors, bus sips, pass-the-pencil times, the roulette minimum stake; for duels first-to in rock paper scissors, one creature or a team, and for 8-ball the table colour, ball behaviour and shot clock). They are kept per game in the lobby (also for Play again); the others see them read-only, and the server checks them like a scene's settings. Drive the bus and Pass the pencil require teams. A duel requires at least two players. The round selects two at random and everyone else can vote for the winner. **Play** sends every phone in the lobby into the round. The other players see the same picker read-only (no Play button), with the leader's game, teams and team making following along within a few seconds.
5. The leader runs the round from their phone. For Count the Dots and other shared-screen minigames, the leader can tap **Set up shared screen** before starting. Open the screen in a new tab or copy the link to a TV browser. For duels, the link is in **Leader tools**. With a shared screen, Count the Dots keeps the pattern on the screen and the guess on the phones. The screen is optional: while no host or shared screen is connected (in the arcade or in any room), each phone shows the dots to count until guessing starts and plays their count-up at the results. Phones also show the live race bars in Tap race, how the other players or teams are doing in step games (Drive the bus, Lucky doors, Left or right, Speed run), and play the coin toss and the roulette spin. At the results every phone shows everyone's places and points under its own result (three per page), for every minigame. In a duel, phones show everyone's points and, in pool, the table and the round's points too.
6. Back in the lobby everyone sees the last round's results and the **total in this lobby** (points, wins, rounds played).

- The arcade page also shows the all-time **leaderboards**: most wins, and the best result per minigame (played alone). Only people with a personal key are on them; guests count in their lobby's total only.
- If the leader leaves or is gone for 45 seconds, the player who joined first among those still there becomes leader. Someone who arrives during a round plays in the next one.
- A lobby that nobody has been in for 15 minutes closes by itself (a round still open there ends without results).
- Limits: 40 open lobbies, 24 players a lobby, 10 new lobbies a minute per address.
- Like hosting, the arcade only runs in the test version, never in production (until sign-in exists). Each round is an ordinary room hosted by the arcade, which nobody can join with its room code or take a seat in: only the lobby's members are seated. Code: `apps/server/src/arcade/` and `apps/web/src/arcade/`.

### 6. Device logs: what went wrong, and how a game ran

Phones and screens keep a short log of what happens on them: what was tapped, which requests and room commands went out, what came back and how long it took, connection changes and script errors. Nothing is sent while things work. Players keep seeing the ordinary "That did not work" message; the details go to you.

- **When something goes wrong** (the server fails, a request gets no answer in time or there is no connection, a command is not confirmed, a script error), the device sends its log by itself a few seconds later. It sends at most once a minute.
- **When a game ends**, every device that played sends its whole log once, with figures: typical and slowest server answer, connection round trip, how often the page was busy, and reconnects.
- **The server saves its own unexpected errors** too: where it happened, the error and the first lines of its stack, with the request id.

For you: owner menu → **Device logs** (`/?admin=logs`).

- *Problems*, *Finished games* or *Everything*. Search by room code, player, error code or request id.
- Open a log for its figures, the server errors that belong to it, and the timeline (failures in red). **Copy as text** gives everything to paste into a request to fix it.

In **Admin → Health**, retry room updates that have stopped retrying, clear undelivered updates more than a day old from disconnected, finished rooms, or mark recent problem reports as reviewed. Room answers and scores remain available, and reviewed reports stay in **Device logs** until the normal retention period ends.

A log never holds what was typed, field values, passwords, keys, tokens, cookies, or the part of an address after `?` or `#`. Ids are cut to 8 characters. Logs are kept 7 days (at most 20 000), stored in PostgreSQL (`device_logs`, migration `20261125120000_device_logs`). Limits: 300 events of the last 30 minutes per device, 160 KB per log, 60 logs a minute and 600 an hour per address. Details and what is still open: [device logs](docs/product/device-diagnostics-plan.md). Not yet checked on real phones on a real network, or on Safari/iOS. Code: `apps/web/src/diagnostics/` and `apps/server/src/diagnostics/`.

## Authentication boundary

Creator sign-in provider selection is deferred. There is **no development login bypass**, password store, sign-in screen, or token-issuing endpoint.

The backend can verify API access tokens from a configured OIDC provider using HTTPS JWKS, RS256 signatures, issuer, audience, subject, expiry, issue time, and a one-hour maximum token age. Set `AUTH_ISSUER`, `AUTH_AUDIENCE`, and `AUTH_JWKS_URL` together. Tokens are sent using an Authorization Bearer header. Configure a dedicated API access-token audience; this is not a browser ID-token login flow.

`/api/me` requires a verified identity. `/api/ops/metrics` also requires the trusted issuer's `ops:read` scope. A browser cannot grant itself scopes by sending IDs or role flags. There is no frontend token storage yet.

With no provider in development, protected endpoints return 503 and readiness is 503. Production startup refuses missing authentication configuration. Liveness stays 200 so a deployment does not endlessly restart just because sign-in is unconfigured.

Room networking now separately verifies expiring/revocable opaque host/display/player credentials in HttpOnly cookies, checks roles/origins and bounds admission/messages. Normal room creation requires verified OIDC identity and ownership. The owner-run rehearsal CLI explicitly provisions a short-lived host grant for one test room; production rejects those local rehearsal grants. Full creator browser sign-in/provider integration remains future work.

Back to lobby: in the host panel, **Back to lobby** (it asks first) starts the same game again in a fresh lobby, also after the game is over. The room gets a new code; phones and the shared screen move along by themselves, with each player's name, look and personal account, and the host's room settings carry over. The old room ends as it was, so its scores and answers stay in the history.

When time runs out, a phone sends what the player had chosen, typed, ordered, uploaded or drawn but not sent yet (the server takes it during its grace period: 1 second, or 3 seconds in drawing rounds, where a line still being drawn is kept too; a very slow connection can still miss it).

Room screen: the connection is a dot in the top bar (its menu: status, *Reconnect and sync*, measurements); the round is one line of chips (what to do now, a player's team as a coloured flag, the time) with an (i) for the details; the host panel has the main buttons, a row of icon tools (pause, smoke break, a quick time button of 30 seconds unless the game sets `quickTime`, the stopwatch with more time options, reopen) and four icons that each open one sheet (Room settings, Shared screen & invite, Players, Back to lobby); the scores are a small foldable card (bottom of the host panel, a corner of the shared screen), shown big only at scoreboard scenes and the end. A round people play can show an **intro before the round** (scene setting): the round waits, untimed, while everyone reads it and players tap *Got it!*; the host sees who is ready and starts the round. The intro shows an explanation, the **points at stake** (worked out from the round's own scoring, so it follows changes: "Up to 15 points", "2 points per vote, +5 for the most votes"; switched on by default for rounds that earn points) and/or a picture from the media library; set to *Only on the shared screen*, phones show "Look at the screen" and nobody taps anything. Duels have no intro. A minigame can use its standard "how to play", which each game can reword in Look & feel → Texts → Minigames.

**Host phone and auto-reveal.** Open **Players → Host phone** on the host screen and select a connected player. That phone still plays and can use **Host controls** to start, pause, resume, close, reveal, or advance a round when available. Select **None** to revoke the controls. A replacement phone taking over the seat needs a new assignment. Turn on **Automatically reveal results** in **Room settings**, the phone's **Host controls**, or **Game settings → Host tools** for new rooms. Use a delay of 0 for immediate reveal after closing when results are ready. The host can still reveal manually.

**Voting and results.** A Vote part can offer one choice, multiple choices, or ranked choices. Ranked ballots give the maximum number of selections as points to the first choice, then one point less per rank. Vote, drawing, and photo or video upload results can use individual cards, advanced by the host or at a set interval. **Game settings → Host tools → Private birthday vote** adds a player-only vote through **Menu**. A majority prompts eligible players to sing. Drawing and minigames can start with a countdown of 0–15 seconds after **Explanation first**.

**Leaving and closing rooms.** Players can return to the join screen from **Menu → Leave room** or the finale after confirming. Hosts can close a room for everyone from **Room settings** or the host menu. In **Game settings → Host tools**, set how many minutes a party room may stay empty before it closes (0 disables the timer). A host or player reconnecting resets the timer. **Keep this room open** overrides the timeout for the current room.

**Player moderation.** The host can change a name or photo for the current room, remove a picture, or kick a player. A room ban prevents a signed-in account from rejoining that room. Guests can be kicked. Correct scores uses one form with a player selector and a signed point adjustment.

Characters are put together from a body, colour, eyes, mouth, hat and an extra, and optionally facial hair (stubble, goatee, full beard, handlebar moustache, mutton chops), piercings (nose, septum, lip, eyebrow, cheek studs) and tattoos & marks (heart, star, teardrop, lightning, scar, beauty mark, unibrow). *Surprise me* sometimes adds those too.

**A game's own room settings.** In the editor, **Game settings → Room settings** sets what a room of the game starts with: whether players see the scores during the game, reactions and how many per 10 seconds, break votes and how many must agree, and whether a round ends soon after the last answer (and after how many seconds). The host can change them in **Room settings**, except ending a round: once the game has started, that stays as the game set it (shown greyed, *Set by the game*). In an imported game: `"room": { "showScores": false, "autoCloseSeconds": 5 }`.

Looks: unless the host ticks *Players confirm their look before it is used* (Room settings), every choice in the look builder is used at once, and a drawing in progress is used when the player taps Done or the game starts.

Seat takeover: a player whose phone died opens the room on another phone, chooses "Take over my seat" and picks their seat. Only seats with no phone connected are offered. A room setting decides whether the host must approve first (off by default); either way the old phone's access is cancelled and the score and answers stay with the seat.

Local owner hosting is the explicit non-production stand-in for creator sign-in. The owner link carries a generated key once; the browser then holds it in an HttpOnly, SameSite=Strict cookie scoped to `/api/host`. Startup refuses `LOCAL_OWNER_TOKEN` in production, and rooms opened this way use rehearsal grants that production rejects. Hosting on a production deployment therefore still needs a chosen sign-in provider.

## Logs, timing, and health

- Fastify/Pino JSON logs include generated request IDs, version, route, status, duration, and errors. Request serializers omit headers, query strings, and bodies; configured sensitive fields are redacted.
- `Server-Timing` measures server work through response preparation. Completion logs/metrics measure the lifecycle through response completion. Neither includes phone/network/render time.
- `/api/health/live` reports process responsiveness. `/api/health/ready` checks authentication configuration and database connectivity. It does not prove provider availability, schema compatibility, or game readiness; migration/deploy checks are separate.
- `/api/ops/metrics` exposes fixed-size duration buckets, error/request counts, event-loop delay, memory and uptime to authorized operators. It also includes database pool measurements and last connectivity-probe timing. Metrics reset on process restart and are not a persistent monitoring system.
- Optional manual request spans export over OTLP/HTTP when `OTEL_EXPORTER_OTLP_TRACES_ENDPOINT` is configured. No exporter or external network telemetry is enabled by default. Request spans are currently standalone; database spans and full browser/server trace correlation come later.
- SIGTERM/SIGINT trigger a bounded shutdown. Fatal exception monitoring logs available diagnostics without swallowing the crash. An external host/process supervisor is required for restarts.

Never commit `.env`, credentials, answers, or recovery codes in logs. The owner's device logs (section 6 above) keep unexpected server errors and device problems for 7 days; full error issue tracking, persistent dashboards, telemetry outage testing, and deployment alerts remain future work.

## PostgreSQL and code-first migrations

One database per environment holds both authoring and live-game tables. Sessions reference immutable game versions; both editors will use the same editable draft. See the [schema and migration guide](docs/architecture/database.md).

```sh
npm run db:env             # create ignored local credentials if .env does not exist
npm run db:up              # start persistent local PostgreSQL
npm run db:migrate:deploy  # apply reviewed migration files
npm run db:status
npm run db:test:up         # isolated disposable test service
npm run db:test           # migration and integration checks
npm run db:test:stop
```

Use Prisma **7.10.1** commands, not the current Prisma 8 prerelease workflow. There are seventeen migrations; the latest seven add feedback reports, people with side-game chips, personal keys with editor rights, scene prefabs, challenges between players, chip stakes for those challenges (before it, accepting a challenge with a stake failed), and the arcade (lobbies, members, rounds, seats and results, with at most one unfinished round per lobby). Uploaded files are stored in `.local/media` (or `MEDIA_DIR`), not in the database. `npm run db:migrate:create -- --name describe_change` generates SQL for review; `npm run db:migrate:dev` applies it to a guarded local development database. `npm run db:generate` is also run by root build/test/typecheck commands. No database is reset or migrated automatically by the web server.
